# Mycel

Mycel 2 is a Python command line for maintained repository knowledge.
Its command line is its only product interface. Each invocation ends when
its operation finishes; it provides no caller library or resident service.

Read-only diagnostics expose settings/store faults and configured model
identities. Complete repository status separates disk and branch/stash-only
content, full current-model version/part coverage and the last pass. `status
--all` includes indexed disabled and orphan names. `repos remove <name>` removes
only that repository's indexed state atomically, preserving source files and
other repositories' evidence under the existing nonblocking removal guards.
Each selected repository keeps its own result even when every member is refused.

The SYL-98 foundation supplies finite dispatch, JSON/error/exit behavior,
internal model/subprocess safeguards and requirement coverage gates. SYL-99
adds strict immutable settings, settings diagnostics in `info`, and settings-independent
system grep. Repository resolution and `repos` listing, private credential access,
offline lossless embedding plans, document/code splitters, source declarations,
read-only capture, a shared typed source resolver, exact dependency evidence
and whole-file identity and dependency reconciliation planning are also present.
Parser-derived rename identity and the reusable transaction-bound mutation
activity API are implemented, including exact final reply accounting and
read-only invocation liveness over injected transaction callers.
The prepared `mycel grep` integration runs the first grep on PATH with literal
arguments and its own streams/status, then can append at most five ordinary combined
search results without freshness or store writes. Counts, filename-only and
quiet modes, pattern files, unknown options, short patterns, failed grep and
non-repository scope suppress the tail; `MYCEL_GREP_PLAIN=1` always selects
grep alone. An optional search failure leaves grep's completed status intact.
Fourteen kind-matching MYC-10 proof lists are prepared for complete validation.
This SYL-135 source preparation has not completed acceptance; passing focused
checks do not replace the required fresh complete development/installed pair.

```sh
PYTHONPATH=src .venv/bin/python -m mycel --help
make check
make check TESTS=test_store_gate
```

`make check` uses the prepared `.venv/bin/python`, six worker processes and
`~/.mycel/config.toml` for the disposable-store server. `TESTS` accepts module,
class or method names, including several space-separated selections. Override
`WORKERS=6`, `STORE_SETTINGS=/path/to/config.toml` or
`REPORT=/path/outside/repo/report.json` as needed. A focused run proves only its
selected methods; full acceptance requires the complete gate. The check guide
explains process isolation, server preflight and cleanup of recorded databases.

Python 3.13 or newer is required for development. A development environment
may install the project with `pip install -e .` to get the `mycel` command.
Mycel supports Apple Silicon Macs (`macos-arm64`, macOS 14 or later).
The development `mycel_build` module stages pinned self-contained Builds and
a separately pinned bootstrap launcher. The installed launcher selects intact
working Builds numerically, preserves the caller process through execution and
accepts an explicitly named withdrawn Build with its reason. Working publication
and complete installed-release qualification remain unfinished.
