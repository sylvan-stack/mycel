# Dependency reconciliation and guarded application

`mycel._reconciliation.plan_dependencies` stages finite dependency, role and pin decisions for one exact dependant version. It writes nothing and makes no provider, network or database call. The private `DependencyApplicationStore` and `LocatedDependencyProducer` apply those decisions inside complete located publication. Every complete located publication now performs mechanical staleness detection automatically after both corpora and dependency/collection handoffs. Public `derive` asserts and withdraws a selected dependency through the exact guards. Guarded current-version relation retention and missing-source withdrawal use the same checked publication boundary. Complete public ingest composes these boundaries; confirmation and atomic repository removal use their public guarded producers.

The planner consumes the central [resolver](parsing.md), validated immutable [baseline manifests](evidence.md), and the version selected by [identity reconciliation](identity.md). It returns immutable decisions and a complete proposed authoritative dependency graph, or refuses the whole operation before returning a usable plan.

## Inputs and ownership

- `DependencyRecord` holds one existing dependency's stable matching identifier and immutable `BaselineManifest`. The manifest records the original source place/declaration, exact dependant version, selection membership and pinned comparison. Separate optional `retained_place`, `current_anchor` and `current_declaration` fields hold the latest recognized source binding. They allow a recreated source with a new current ID to move again without modifying its old audit baseline.
- `DependencyRequest` contains the matching identifier, `declared` or `asserted` kind, complete raw declaration and, for a previously resolved missing source, an explicit `away` or `deleted` observation. Resolver absence alone cannot distinguish these states. A never-resolved missing ref stays unresolved even when its absence is known.
- `pin_version` selects exactly the dependant version whose records the caller supplies. The supplied dependant must equal the enabled catalog's exact endpoint. Existing records belonging to another dependant/version are refused.
- `graph` contains the complete settings-eligible current authoritative graph, including unaffected declared/asserted/generated dependencies across repositories. Graph entries carry source and dependant stable identifiers plus the owning dependency identifier. Relations are excluded because they have no authority. This identifier-only graph cannot independently verify repository enablement or catalog completeness; the guarded caller must do so.
- `baseline_faults` explicitly identifies previously resolved dependencies whose old evidence is missing, corrupt or unsupported. They refuse the operation visibly and cannot be treated as initial resolutions that capture today's text. This conservative seam does not perform evidence reconstruction or cleanup of damaged ownership graphs.

Dependency identifiers must come from one globally unique allocator across kinds and dependants. A new requested identifier colliding with an unaffected graph dependency is refused, including generated dependencies; it cannot displace that edge. The caller must match existing dependency identities and deduplicate equivalent same-kind selections before planning. Keeping an existing identifier across raw spelling/qualified alias changes does not authorize repinning. The planner refuses duplicate canonical same-kind selections with different IDs, changed dependency kinds, and same-ID binding to an unrelated target. A resolved move requires the same retained current anchor identifier; a recreation at the same natural place may have a new anchor. An unresolved/ineligible target supplies no identity proof: it must retain the recorded raw declaration or identify the same literal natural selection.

`requests` includes every current declared ref for the selected location and any newly asserted/current assertion observations. An omitted declared record schedules release of that declaration's ownership. An omitted assertion survives and is resolved again; provide its explicit absent-state observation when its source is missing. `AssertedRemoval` selects the canonical natural place and selection kind. It removes only an assertion for that selection/dependant, including an absent retained source. Removing an absent assertion is a no-op; a file-wide selection cannot accidentally remove a chunk/family assertion.

## Decisions

| Observation | Decision | Governs role |
|---|---|---|
| First eligible resolution | Schedule `capture`; no baseline exists yet | Yes |
| Eligible existing resolution during observation/restoration | `keep` its own baseline | Yes |
| Normalized-equivalent edit or recognized rename | `inherit` the selected reference-version baseline | Yes when eligible/present or retained missing |
| Accepted substantive dependant edit or owner confirmation with present source | Schedule authorized `capture` | Yes |
| Previously resolved source away/deleted in an enabled repository | Keep exact baseline, report `source_removed`, no live source endpoints | Yes |
| Previously resolved missing source during accepted edit/confirmation | `withdraw` retained dependency; remaining raw ref stays a visible missing fault | No |
| Disabled/unregistered target | Keep old baseline inactive and retain its invalid fault/raw declaration | No |
| Never-resolved/ambiguous/malformed reference | Visible unresolved/invalid decision without invented baseline | No |
| Declared ref removed or matching assertion explicitly removed | Release only that dependency's references | No |

The planner preserves the complete typed `Resolution`, including ambiguity candidates/count, for reporting. A resolved decision supplies `ResolvedBinding(place, anchor, declaration)` for the transaction executor to persist independently of the unchanged baseline. This updates current natural binding after recognized moves/recreation; the manifest's original address/ref remains audit evidence. Unresolved decisions supply no new binding and preserve their retained one.

Empty exact files remain present even when they have no chunk endpoints, and still govern the dependant. File selections compare complete file bytes; family selections compare ordered natural membership plus each member comparison. Added/removed family members cannot disappear behind the old member edges. A lost family member reports `source_removed`; a changed complete family comparison also reports `source_changed`. The old complete manifest remains unchanged until an authorized replacement commits.

Every resulting current member supplies a source-to-dependant graph edge. Owned edges being reconciled are replaced while unrelated graph entries remain. An iterative deterministic walk checks the whole proposed graph, including all expanded file/family members, and reports an actual closed path for self/circular dependencies. No partial mutation plan is returned. New invalid/unresolved/ineligible refs similarly refuse confirmation before any decision can be applied.

Role is recomputed: any current incoming authoritative edge or eligible retained missing dependency gives `derived`; otherwise the supplied file role, otherwise `authored` for code and `unclassified` for a document section. Retained inactive baseline evidence alone does not govern a disabled repository's sources.

## Authorization and transaction boundary

`mode` is a typed decision context, not authorization obtained by the planner. The guarded producer derives it from the accepted identity decision and owner action. `observe`/`restore` use the current exact version's own records. Normalized-equivalent document edits inherit selected reference-version pins; a code name rename first passes `inherit_baseline` with the retained complete previous file and the separately versioned MYC-D38 parser identity projection. The planner then validates the already verified prospective dependant manifest, while the evidence writer independently repeats the rename verification. Complete-code comparisons and exact bytes retain their original meanings. A substantive dependant edit authorizes replacement capture; changing another chunk, frontmatter, file metadata or source text does not. A newly declared link still follows initial-resolution capture.

Frontmatter is excluded from stored Markdown chunk bytes but can attach source declarations to the first chunk. Two located files may share one exact chunk version while their declarations differ. Ownership is therefore selected by repository, exact dependant version and the concrete file-location UUID. A reused location UUID can hold separate historical version records; restoring a known version selects its own records. A new branch/stash location starts its own pin ownership unless the identity producer explicitly supplies a checked reference location. The located producer never automatically falls back to a later disk version's pins.

`DependencyApplicationStore.apply_in_transaction(settings, file_location, dependant_version, ...)` requires the caller's active native transaction, checked store structure guard and complete configured repository pass/removal guards. It loads the selected file's complete stored bytes, reparses declarations, checks the exact dependant endpoint and selected reference version, and validates every old baseline's manifest, snapshots, owner identity, ordered references and retained exact dependant bytes. Missing, corrupt or unsupported old evidence refuses the operation visibly instead of becoming an initial capture of today's text.

Declared matching is independent of occurrence order and raw qualified/legacy alias spelling. Equivalent same-kind selections share one dependency and pin, with every declaration occurrence retained in state. Asserted dependencies survive omission and removal matches their natural place plus selection kind. The executor allocates real dependency UUIDs for new versions and returns the logical-to-persisted identifier map; it never overwrites a prior version's dependency or another location's ownership. Removed declarations with no baseline are released too.

The immutable baseline and persisted audit declaration keep their original source/ref. Current raw spelling, canonical source binding, anchor, complete selected member list, source state and visible typed resolution are updated separately in the dependency state and `source_place`. `RetainedDependencyResolver` uses an existing stable anchor only after ordinary resolution is absent, following recognized file moves or accepted chunk-name changes. A new ambiguity, disabled repository or newly resolved natural place keeps ordinary resolution's result. Recreated sources can reconnect at the same natural place without renewing evidence.

The executor reads the complete settings-eligible authoritative graph for the selected catalog/location, including declared, asserted and generated owners and index generation endpoints. Relations supply no authority. Current full file/family members become edges to their exact source-version rows. The pure planner checks the entire proposed graph before effects apply, including unrelated generated authorities; a cycle returns an actual closed path and aborts the caller's publication.

Every application, including observation, restoration, release and malformed/unresolved declarations, freshly guards complete dependant bytes and location/settings metadata. Every current decision additionally guards its source selection or explicit absence through a caller-supplied fresh rereader. Capture and inheritance repeat the exact input and owner checks through `checked_transaction_input_guard`, `pin_in_transaction` and `inherit_in_transaction`. Accepted edit/confirmation capture replaces the selected owner and clears its answered direct comparison reasons inside the same transaction; withdrawing a previously resolved missing dependency leaves the raw ref visible without live authority or an invented empty baseline.

Resolved edges, visible ref faults, current bindings, source-change/removal reasons and the selected chunk location's effective role commit with evidence and declarations. Ref-change counts describe dependency/ref mutations; role and file-declaration metadata counts are separate. Selected dependency releases use the guarded [collection](identity.md#guarded-unlocated-collection) producer. It captures both baseline and classification-work evidence owners before deleting the dependency, then releases only those now-unowned references and collects wholly unreferenced evidence in the affected owner repositories. Verification, Drift history and live invocation ownership continue to protect old bytes.

`batch_in_transaction` prepares the complete set of exact located chunk scopes before application. Its active connection/settings-bound token excludes only pending scopes' original declared/asserted edges while their complete replacement decisions are staged; unrelated and generated authorities remain throughout. Every prepared scope must finish, and the final complete persisted graph is reread and cycle-checked. This permits an acyclic whole-file declaration reversal without treating the earlier state's edges as simultaneous final authority. Skipped, repeated, foreign or expired batch scopes refuse.

`LocatedDependencyProducer` connects accepted file identity decisions to this executor for every published location. It also observes current location-owned declared/asserted dependencies in enabled foreign repositories whose raw or retained natural selections name the publishing repository. Those scopes join the complete final graph batch before collection. A source-only change, deletion or recreation refreshes their bindings, reasons and roles while preserving each dependant's exact pin and evidence owner. Never-resolved selections retry initial resolution. Historical unlocated ownership and disabled dependant repositories stay outside this producer.

The producer opts into unchanged capture callbacks so settings-only eligibility changes can deactivate or restore authority without inventing file changes. Genuine no-op checks rewrite no feature or audit row. Collection-only changes and unowned evidence removal contribute explicit mutation/count results even when current file identities are unchanged. `dependencyRepositories` reports the affected foreign repositories' ordinary reference/pin/role counts. The caller's pure `reply_counts` callback previews cumulative counts for each owner; caller counters advance only after commit. The outer publication's activity session supplies dependency-only `ingest` entries for actual foreign mutations, with no file or identity details.

The producer reparses complete dependant files and rereads settings, physical disk sources and retained Git sources without substituting another location's text. Retained absence records separately expose `sourceExistence` as `away` or `deleted`, plus `sourceAbsence` with the retained qualified place, previous complete-file hash where known and first observation time. Repeating an identical absence keeps that observation. The reporting `sourceState` and reasons retain `source_removed`; empty present files retain exact empty evidence. A missing selected source validates all relevant raw-path and retained-natural-path files across indexed versus physical locations, including retained anchors, so stale or newly unindexed branches cannot manufacture absence evidence.

Called directly, the complete capture producer rechecks its physical/Git manifest after all handoffs and immediately before commit, the dependency producer's connection/result-bound final check rechecks foreign acquisitions after reply and downstream audit callbacks, and late source, dependant, settings or Git changes roll back the entire publication and every affected audit. The complete public pass passes `publish_capture` instead (MYC-1.37, MYC-D64): it publishes the capture it read, observes its own repository through that capture, takes another repository's sources from the index without comparing that repository's disk, and names what moved meanwhile under `changedDuringPass`; only a settings change or a changed store catalog still rolls it back. Optional unlocated collection runs only after dependency/evidence application has finished. Public ingest composes this boundary as described below. Generated authorities and final requirement acceptance retain their owning tasks. Mechanical stale propagation uses the complete publication seam described below.

The older `DeclaredRefStore.retain_in_transaction` and `recheck_in_transaction` remain conservative low-level adapters; replacing pinned declarations through those adapters alone still refuses. Evidence capture alone does not authorize graph, role or declaration changes. Production transaction composition uses the complete policy executor and the selected identity version.

Configured executor proofs cover alias/dedup ownership, disk-only declared removal, asserted alias matching and selection-specific removal, file-wide away state with a surviving branch pin, incomplete baseline ownership refusal, ordinary/generated/index cycle checks, missing-guard/foreign-version refusal, and incomplete/expired batch refusal. Complete located-producer proofs also exercise inheritance, accepted repins, withdrawal, restoration, physical changes and rollback with activity. The local dependency contracts have named configured-store proofs. Classification, relation and verification producers, Drift consequences and full repository removal have their own feature checks; complete packaged Build qualification remains separate.

## Retained relation source transitions

`RetainedRelationStore.apply_in_transaction` observes one existing relation at an exact dependant version and file location. Its immutable `related` baseline is checked against the retained owner, ordered references, complete snapshots and old dependant version. Relation state retains the current `rawRef`, immutable `baselineRef`, declared/asserted `ownership`, checked `declarationLocation`, natural source place and current anchor. This boundary creates no initial relation or baseline; those producers remain in the relation task.

The shared resolver reconnects a recreated source or recognized move without changing the baseline. Missing current sources retain exact old bytes and a separate `away`/`deleted` observation with the prior file hash and observation time. Empty file evidence stays present. A missing family member gives `source_removed`; a changed current selection gives `related_changed`. These direct reasons belong to the selected exact dependant version. Relations create no authoritative edge, derived role, cycle restriction or propagated reason.

A guarded owner confirmation withdraws a previously resolved missing baseline while keeping a declared selection's visible resolution fault. A verified substantive edit can create the current version's unpinned fault while preserving the historical version's own relation and evidence. The complete located handoff resolves withdrawal candidates freshly, including a source deletion and dependant edit in the same capture before the old relation observed absence. Normalized edits, present-source repins, ordinary relation inheritance and public verification remain the later producers' responsibility. Selected removal releases only that relation owner; surviving history still protects shared evidence.

`LocatedDependencyProducer` refreshes current retained relations in affected enabled foreign repositories alongside dependencies, before source collection. Relation counts and actual foreign mutations join the publishing transaction and its cumulative activity reply. Repeating an identical absence is quiet. Complete source, dependant, settings and relevant disk/Git inputs are rechecked after every reply and audit callback; a late change rolls back source publication, relation state and activity together.

Configured proofs in `tests/test_dependency_contracts.py` cover complete file/family pins, membership changes, declaration removal, role recomputation, sibling/frontmatter no-repin behavior, authorized direct-comparison renewal, all-or-nothing confirmation faults and actual branch/stash version restoration. `tests/test_retained_relations.py` proves removed and recreated source retention, empty-file evidence, confirmation/edit withdrawal, same-capture withdrawal, family membership removal, selected relation isolation and late foreign-input rollback. The claims register these local dependency/source-transition contracts; initial relation/public command producers and verification remain separate requirements.

## Guarded public assertions

`mycel derive [--remove] <dependant> <source>` resolves one current disk dependant through the central endpoint resolver and a complete file/chunk/family source selection. Index selections, disabled/unregistered repositories, ambiguous roots/headings and missing new assertions are refused. File and family expansion participates in the complete graph cycle check before any effect. The command never ingests or confirms a dependant, source or declaration.

`DeriveStore` holds checked-store and every configured repository's pass/removal guards. Its exact assertion-only scope supplies the selected asserted dependency ID (or an empty tuple for a new assertion); a foreign ID is refused. All declared rows and unrelated asserted rows, occurrence metadata, edges, faults and evidence owners remain byte-identical. Their eligible live authority and retained missing/empty-file authority still participate in graph/role calculation. Ineligible or ambiguous retained evidence supplies no fallback authority. Existing current exact version/location ownership is never borrowed from a branch or stash.

The shared `DependencyCaptureInputs` rereader protects complete dependant/source files, raw candidate sets, settings and relevant retained source locations. Removing a selection guards its resolved bytes or explicit absence even though a release decision has no active source resolution. A checked retained anchor is copied under the user's alternate natural spelling so all away witnesses remain checked. Physical source/dependant/settings or Git changes before publication—including changes during activity attachment—roll back all feature, evidence and audit writes.

Repeating the same assertion preserves its original raw spelling and immutable baseline, including equivalent qualified/legacy aliases. A real assertion/removal atomically commits numbered-Build `derive` activity with the exact final reply; an identical assertion or absent assertion removal creates none and does not collect unrelated unreferenced evidence. A real writing mutation still collects wholly unreferenced owner evidence. Source development does not invent an installed Build identity. Damaged selected baseline ownership remains a visible refusal rather than an implicit repin.

`--remove` matches only the selected assertion's natural place and file/chunk/family kind, including retained away/deleted source records. It releases that owner while verification/history references continue protecting shared bytes. An absent assertion is a successful guarded no-op. When the source itself has no current resolution and no retained selected assertion, the reply has `source: null` plus the literal `sourceRef`; it does not return a guessed canonical Place. Other replies use qualified places, exact dependant version, action, changed state, selected member count and an assertion's persisted manifest identifier.

`tests/test_derive.py` exercises exact CLI syntax and dispatch, canonical/alias no-op baselines, selected owner isolation, file/family/member separation, self/expanded/multistep cycles, retained away/deleted withdrawal, new ambiguity and stale physical/recreated inputs, orphan-evidence no-op and late audit/settings/source rollback. These checks establish this command slice; relation removal and packaged task acceptance remain separate.

## Mechanical staleness after complete publication

`LocatedCaptureStore.apply` always runs `MechanicalStalenessStore` after the complete disk/branch/stash publication, including both document and code corpora, and after any dependency and collection handoffs. Source changes and all acquired downstream marks commit together. Detection also runs on an unchanged capture, so a pending owner can be retried without another text edit. It does not create or renew a baseline, ingest a foreign dependant, call a provider or open a public command.

Direct comparisons use the current central resolver and the retained immutable baseline. A section uses its supported body comparison; code uses exact code bytes; a file uses every original byte, including frontmatter; a class uses ordered membership and member comparisons. Removed family members receive their own qualified `source_removed` places. A source absent from disk is removed even while a branch or stash retains it. A never-resolved ref remains a reference fault. Disabled and unregistered sources supply no current authority or propagated stale reason.

The pure `compare_dependency` and iterative `plan_staleness` functions decide mechanical reasons without I/O. The complete current selections expand file and family edges, including newly added members when old stored edges have not yet been refreshed. Every direct reason precedes every indirect reason; independent edge kinds and distinct paths through a diamond survive. Each indirect reason retains the original source and every intermediate qualified Place in source-to-dependant order. Current Heartwood and externally generated document declarations clear their marks and stop propagation. Changed bytes of those documents still compare directly for a dependant. Index-only Mycel summaries and their later generation hooks are outside this document exemption.

Detection acquires only potentially affected repositories' pass/removal guards without waiting. A busy owner retains its marks and appears in `stalePending`, while acquired descendants can use the complete checked observations. Missing/corrupt/unsupported baselines and pre-existing unindexed participating files remain pending without clearing stored marks; dependent uncertainty stops at exempt nodes. The final guard rechecks settings, the scoped current catalog, participating dependency/baseline/evidence rows and exact physical file/path-candidate observations. A late relevant change rolls back publication and activity. Disjoint metadata commits in an unrelated repository do not invalidate the source pass.

Each affected repository reply reports `staleChecked`, `staleChanged`, `staleReasons` and its total current-disk `stale` count. `staleReasons` counts the applied or retained reasons of checked chunks; `staleChanged` counts actual changed reason sets. A cumulative reply callback adds these per-pass processing counters and preserves the latest `stale` and `stalePending` snapshots. The initiating reply also returns exact pending chunk places and causes in `stalePending`; foreign counts appear under `dependencyRepositories`. Foreign dependency and detection mutations share one cumulative `ingest` activity entry with no invented file/identity details. Identical mechanical reasons retain their row IDs and classification attachments. Complete source, foreign and detector checks run again after the initiating activity attachment, inside the same transaction.

`tests/test_staleness.py` supplies the scoped MYC-2.13–MYC-2.18 proofs: pure actual hash/membership decisions and a deep iterative graph; same-pass code/document changes, all diamond paths and partial recovery; independent kinds, family additions/removals and expanded locks; disk/branch shared-version ownership; exemptions and transitions; busy/pending retry, disjoint concurrency, corrupt evidence, unindexed bytes, final physical/catalog guards and exact activity rollback. Stale/status reporting, confirmation, classification/Drifts, generated summaries and installed Build acceptance remain their separate tasks.

## Complete public ingest

`mycel ingest [--repo <name> | --all] [--embed] [--confirm-empty]` runs a complete pass for each enabled settings-selected repository. Repeated names are deduplicated; organizations expand to enabled members; absent selectors resolve from the current directory. Invalid, disabled or busy requested repositories retain local refusal details, including an entirely refused scope. If none can run, the common repository envelope preserves every member and exits 1.

Each requested pass holds its own nonblocking pass/removal guard before capture. It reads the dirty disk, every local branch and every stash, including untracked stash files, through read-only Git commands. Remote refs are excluded. A refused or incomplete capture publishes nothing and cannot delete absent rows. A capture that the disk or the Git store has moved past is published as it was read (MYC-1.37): before it saves, the pass reads the disk once more and names every differing file and location under `changedDuringPass`, and the next pass takes them up. Every file hash, stable identity, exact version, location, dependency baseline and applied identity decision joins the same atomic publication. The settings, the store's catalog rows and the Git rename correspondence are rechecked after policy, collection, detector and activity callbacks; the physical inputs are not, because the pass publishes its capture. Every transaction of a command allows a statement sixty seconds (it was five until 20 October 2026, when three passes beside the suite cancelled `status` and a pass's own counts with `QueryCanceled`, SQLSTATE 57014); lock waits stay at one millisecond, so a busy repository is still refused at once.

`scripts/check_real.py` is the real-repository check of this boundary: it copies the corpora of `arbol` and `mycel`, ingests them with the `readonly` clones into a throwaway `mycel_check_real_` database twice, changes one Markdown file of a corpus copy during the first pass of `mycel`, and then runs `search`, `read`, `refs`, `stale`, `status` and `embed --dry-run`. It ends with status 0 when every pass and command does, the first pass names the changed file, the second pass takes it up and nothing else changed, and no reply carries `internal`. Its JSON report belongs outside every corpus and repository (`--report`).

Source and prospective declared targets, valid unresolved targets, retained natural addresses/assertions and their authority ancestors determine the required source guards. Foreign refresh and mechanical detection observe only references targeting the requested source; other references in the same chunk retain their rows, pins and direct stale reasons as graph context. A busy required source refuses the requested publication; a busy affected dependant retains its state and is reported in `dependencyPending`. Its source deletion cannot cascade an unheld edge: collection also remains explicitly incomplete in `collectionPending`, until an unchanged retry can acquire the owner. Disabled foreign owners receive only the narrow guard needed for actual source-edge collection, with `sourceEdgesCollected` in their activity; their files and policy are not ingested. Disjoint busy or concurrently publishing repositories do not prevent the selected pass. Catalog file/chunk projections are read in one SQL statement so concurrent unrelated publication cannot mix different MVCC snapshots.

A declared source that has never been indexed remains visibly unresolved even
when its file already exists in another enabled repository. Ingesting the
dependant alone records no source rows, edges or invented baseline. A later
named source pass retries the reference and captures its first exact baseline;
`--all` also works when the dependant sorts before its sources. Complete physical
captures still have to stay unchanged, and previously resolved or pinned sources
retain the stricter exact indexed/current checks.

After a complete unblocked publication, collection immediately removes every unlocated exact version and every chunk/file with no surviving version. Branch/stash locations continue protecting their exact text and vectors. Surviving dependant-owned snapshots, natural addresses and pins remain missing-source evidence without retaining searchable source rows. A quiet repeat retains feature row identities and produces no activity entry. `last_pass_at` records the successful complete observation time separately from mutation/identity activity.

The complete producer's final transaction hook reconciles each directory's
index-only [overview](overview.md) from applied disk code records, after
dependency reconciliation, collection and mechanical detection. It compares
complete rendered text and counts, replaces changed sections atomically and
deletes empty directories. Body-only edits preserve exact outline versions and
vectors. Quiet passes rebuild missing outlines from stored parse metadata.
Projection mutations join the pass's `changed` decision and numbered activity;
file/chunk identity counters continue counting the captured source inputs.

The per-repository reply reports `ran`, file and identity counters, final current-disk `stale`, and current-model `pending` version counts. It also includes exact embedding part coverage and dependency/detection/collection counters. Refusals add `refused` and a closed `error`; incomplete propagation returns exit 1 with its pending owners or chunk places. Counts accumulate once per actual owner within the invocation and activity copies the final replies. Applied identity decisions are readable through `mycel activity --entry <id>` in numbered Builds. General activity history remains separate work.

Without `--embed`, pending coverage is planned locally using complete retained versions, including provisional multipart plans, and no embedding credential or provider is constructed. Explicit embedding begins only after publication transactions and pass guards have closed, operates on the requested repositories whose publication committed, and uses the ingest embedding authorization. Already committed file and paid-batch results survive interruption, provider failure or final audit/guard cleanup failure. Such cleanup failures preserve the acknowledged repository replies with `countsState: "committed_prefix"`; interruption returns exit 2. Paid live-provider and installed Build qualification remain separate acceptance.
